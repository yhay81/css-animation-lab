# css-animation-lab

CSS アニメーションの表現範囲を、実験と評価の反復で体系化するための研究環境。

CSS だけでできることは広いが、「何ができるか」「何がうまくいかないか」「どう組み合わせると良いか」
がライブラリや知識として十分に流通していない。ここではそれを、数を作って絞り込むことで埋める。

最終的な成果物は 3 つ。

- `catalog` — 全実験を軸で索引した機械可読なデータ
- [FINDINGS.md](FINDINGS.md) — 効いたこと・効かなかったことの記録
- [PATTERNS.md](PATTERNS.md) — 型ごとの性格タグ（注意度・由来・反復耐性）
- 採用された動きを再利用可能な CSS として切り出したもの

**「この用途にはこの型」という対応表は書けない。** 3 階層すべてで「用途による」という答えが返ってきた
（F013・F015）。決めているのは UI 部品の種類ではなく、その場面が持つ性質のほう。
書けるのは型ごとの性格であり、選ぶのは使う側になる。

## 設計の前提

生成はいくらでもできるが、**人間が動きを見て判断する時間が唯一の希少資源**になる。
したがってこの環境は、判断1回あたりの情報量を上げ、判断回数そのものを減らすことに最適化してある。

評価は 3 層に分かれ、人間が担うのは最上層だけでよい。

| 層 | 判定内容 | 担当 |
|---|---|---|
| 機械検証 | 壊れていないか、負荷、合成レイヤに乗るか | スクリプト |
| フィルムストリップ | 動きの軌跡、行き過ぎ、到達の早さ | 静止画として読む |
| 感性 | 気持ちよいか、上品か、その UI に合うか | 人間 |

判断回数を減らす仕掛けは 4 つ。

1. **既定は「採用」** — 何も押さなければ通る。操作回数 = 気になった件数。
2. **事前予測** — 各実験に `good` / `uncertain` / `bad` の予測を持たせ、`uncertain` だけを強調する。
3. **軸の一括切り替え** — イージングは全体に同時適用する。比較対象は常に実験数に収まる。
4. **絶対評価をしない** — 5段階評価は迷いを生むので置かない。却下 / 気になる / 手本 の 3 つだけ。

## 起動

```bash
node lab/server.mjs
```

- <http://localhost:5757/lab/contact.html> — 一覧と評価
- <http://localhost:5757/lab/strip.html> — フィルムストリップ（動きを静止画の連番に開く）

依存パッケージはない。ビルドもない。CSS の研究にフレームワークのノイズを混ぜないため。

## 実験の階層

### T 技法（本線）

**軸は「運動」ではなく「CSS の能力の組み合わせ」。** 何がどう動くかを分類しても、出てくるのは
どの UI ライブラリにも入っている当たり前のものだけだった。探索すべきは、フィルタ合成・ブレンド・
マスク合成・conic グラデ・`preserve-3d`・`counter()`・多数要素といった、**組み合わせて初めて
何かが起きる**領域のほう。各実験は必ず実用の当てを 1 つ持つ。

現在 108 件。何を使っているかは各実験の `axes.technique`、実用の当ては `axes.use` を見る。

### L0〜L4 基礎（土台）

運動そのものの分類。**発見はここにはない**が、技法を語るときの共通語彙と、
測定装置が正しく動いているかの基準線として置いてある。

| 層 | 内容 | 件数 |
|---|---|---|
| L0 原子 | 1 プロパティ 1 運動 | 18 |
| L1 時間 | 同じ原子 × イージング | 一括切替として実装 |
| L2 分子 | 合成の型 | 13 |
| L3 編成 | stagger の間隔と順序 | 9 |
| L4 レシピ | 用途を固定した実例 | 8 |

## 2 つの駆動方式

| 方式 | 対象 | 時計 |
|---|---|---|
| `keyframes` | `@keyframes` + `animation` | `currentTime` で任意の時点に固定できる。スクラブ可、静止画化可 |
| `state` | `transition` / `@starting-style` / `allow-discrete` | 状態変化でしか動かない。実時間で開閉を繰り返す。**スクラブ不可、静止画化不可** |

`state` の実験は `meta.json` に `"mode": "state"` を持ち、一覧では `state` バッジが付く。
`.cell` の `data-open` 属性が 1.8 秒ごとに切り替わるので、CSS は
`[data-exp="<id>"][data-open="true"] ...` で開いた状態を書く。停止（`Space`）には追従する。

## 索引の軸

日付ではなく軸で引けることが、後で知識として使えるかどうかを分ける。
各実験の `meta.json` は以下を必ず持つ。

- **driver** — 何が時間を進めるか（`keyframes` / `transition` / `scroll()` / `view()` / `:hover` / `@starting-style` / View Transitions）
- **target** — 何を動かすか（transform / opacity / filter / clip-path / mask / gradient / offset-path / レイアウト値）
- **timing** — 時間の形（cubic-bezier / `linear()` / steps / 負の delay / `animation-range`）
- **orchestration** — 編成（stagger / 多重アニメーション / `animation-composition`）
- **structure** — 構造（疑似要素 / 多要素 / CSS state machine）

これに加えて、**被写体の下地**が動きとは独立した軸として効く。既定のグラデーションは
「膨らんだ物体」として読まれ、それ自体が判定に混入する（F012）。質感が絡む判定は必ず複数の下地で見る。

## 実験を追加する

`experiments/<id>/` に 2 ファイル置くだけでよい。サーバーが自動で拾う。

```
experiments/<id>/meta.json   # 軸タグ、予測、所見
experiments/<id>/anim.css    # @keyframes と [data-exp="<id>"] への適用
```

`anim.css` の制約は 1 つだけ。**セレクタを `[data-exp="<id>"]` で閉じること**。
これにより全実験を 1 ページに同時展開しても衝突しない。

動きの内部尺は常に `1000ms` 固定で、実時間の速さは JS 側が `currentTime` で決める。
そのため `animation-duration` は書かない。

## 仕組み

CSS 側は `animation-play-state: paused` にしてあり、進行は JS からの `currentTime` の代入だけで起きる。
これ 1 つで「全実験を同位相で比較する」「任意の時点で固定する」「静止画の連番に開く」が同時に手に入る。
